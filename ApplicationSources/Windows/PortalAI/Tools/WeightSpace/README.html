PortalAI Weight-Space Editor

This portable research utility creates a separate GGUF candidate by subtracting a measured direction from selected MLP output columns. It never replaces a live model automatically. It uses the installed Python and native llama.cpp runtime, not a new training environment.

Workflow

  1. Choose your model and Inspect model. The editor checks supported dense MLP tensors. Native evaluation currently supports the verified Windows NVIDIA backend.
  2. Prepare a discovery task file with known answers. Evaluate original saves natural model completions, scores, seeds and timing. Do not select edits using your final benchmark questions.
  3. Locate failure-related sites takes a saved discovery report with at least four successes and four failures. It captures native residual and MLP activations and proposes three single-site recipes. These correlations are hypotheses: differences can reflect problem difficulty or subject, rather than a causal defect.
  4. Inspect the localization evidence. Test individual sites, multiple doses including zero, and a norm-matched orthogonal random direction. Create candidate materializes a model-specific recipe into a new GGUF. Untouched quantization blocks remain byte-identical. Quantization can change neighboring weights inside edited blocks; the receipt reports that error.
  5. Compare candidate uses identical prompts, seeds and sampling on both models. Examine rescues, regressions, cutoff rates and speed. Freeze a candidate before independent paired confirmation, then run separate broad math, coding, tool-use and instruction-following tests. A small local win is not proof of improved general intelligence.

Task files

A JSON list contains 1–256 uniquely identified cases per pass. Supported graders: math (published boxed-answer equivalence), coding (restricted pure Python functions), tool (expected tool calls, never executed), exact, and json.

[
  {"id":"example-1", "kind":"math", "domain":"math",
   "prompt":"What is 17 times 23? Put the final answer in \\boxed{}.", "answer":"391"},
  {"id":"example-2", "kind":"coding", "domain":"coding",
   "prompt":"Write Python solve(xs): return a new reversed list. No imports or mutation. Return only code.",
   "checks":[[[[1,2,3]],[3,2,1]],[[[]],[]]]}
]

The examples above are smoke checks only. Coding accepts bounded pure functions with a restricted AST and builtins; it is not a general OS sandbox. Tool cases supply tools in the model's usual function schema and calls as expected objects containing name and arguments.

Recipe format

A recipe contains method: "sparse-projection-subtraction-v1", the exact base_sha256, a dose between 0 and 6, and one or two sites. Each site specifies tensor, a unit-length output direction, up to 64 unique columns, and their projection coefficients. For each selected column j, the edit is W[:,j] − dose × direction × coefficient[j]. Embeddings, output heads, normalization and whole-matrix rescaling are excluded.

Storage and interruption

Working files stay in the utility's work directory. Candidate creation needs one model-sized copy plus a small margin and always reserves 80 GiB of free space. Original weights are immutable. Stop closes only the owned worker; interrupted candidates retain a .partial extension for review. Nothing resumes or replays an uncertain operation automatically. Review and remove discarded candidate copies when no process has them open.

Method and limits

This is an adaptation of Takehi et al.'s weight-space programming method to actual portable quantized models. Native GGUF execution and block requantization differ from the paper's BF16/vLLM experiment. The utility does not reproduce the authors' editor model, supply missing abilities by itself, or guarantee an improvement. Its numerical and lifecycle tests are separate from evidence about any model's intelligence.

Dependencies: PortalAI's existing BootstrapPython, NumPy/Jinja2/SymPy package layer under Voice/Qwen3-TTS, and the pinned native backend. The small bundled GGUF reader and math graders include their original license files. No reference model or substitute full-precision weights are downloaded.

Reversible profiles

Save a tested candidate as a compact exact profile, then Prepare selected. In PortalAI Settings → Chat models, choose Weight edit profile and Save to use it on the next request. Choose Original weights there to revert. Switching uses a normal model reload. Each profile belongs to one exact model/variant. All current profiles are experimental; no automatic tool replay or model promotion is enabled.

At most two prepared full model copies are cached, with an 80 GiB free-space reserve even during staging. Clear prepared copy retains the original and compact patch. Interrupted or altered files require review. Work runs off the GUI thread. Complete profile and recovery guide.
