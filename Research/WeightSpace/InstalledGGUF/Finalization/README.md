# Finalization source and validation

The campaign is still running. These sources do not imply that independent confirmation or final benchmarks have finished.

The observer holds the original controller process handle, respects pauses, and never retries failed inference or changes scientific settings. After complete confirmation it runs the separate provenance/bookkeeping audit. An audited result that does not establish improvement can finalize the bounded campaign, recheck D/E originals and installers, and publish the final evidence. Positive confirmation stops at the mandatory broad-benchmark gate; it cannot promote an edit.

These are installation-specific publication scripts, preserved for audit rather than a recipient launcher. Their original location is `Maintenance/Validation/Weight-Final-r69`; the public reusable editor is under `ApplicationSources/Windows/PortalAI/Tools/WeightSpace` and the Utilities UI. GitHub publication uses the maintainer checkout and existing Git credentials; neither is required for ordinary portable editor/profile use.

Twenty synthetic CPU tests passed. Three initial IFEval failures exposed excess OpenBLAS thread-buffer allocation; limiting the evaluator to one thread fixed them while retaining a 512 MiB process cap. The actual upstream IFEval code and portable English tokenizer are pinned. Existing SSD Python packages were reused. Only a 4.3 MB tokenizer archive was downloaded and 237,757 bytes of English data extracted; no new LLM or host package was installed.
