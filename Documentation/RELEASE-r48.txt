PortalAI release validation - 2026.10.27-Desktop-r48

Website research now includes provider fallback (optional Brave, DuckDuckGo HTML, Bing organic HTML, DuckDuckGo Lite), direct URL reading, browser-rendered pages, site/domain/path search, observed public GET search forms, and Crossref/DataCite/Europe PMC catalog search. Resource discovery identifies linked documents, data, feeds, images, audio/video and transcript tracks without fetching every link. Structured previews support JSON/JSONL, CSV/TSV, XML/RSS and HTML tables, with bounded pagination and explicit omissions. Catalog records and media metadata are labeled as metadata; they are not evidence of reading a paper or watching a video.

Public downloads are explicit, inert and account-local (8 MiB default, 32 MiB maximum). Existing local file/media tools can process supported downloaded content. Binary Excel/Parquet/archive bytes are not misrepresented as text tables. PDF text reading was exercised; scanned pages need OCR. Live video identification was exercised, not audio transcription or visual video analysis. Authentication, publisher restrictions, rate limits and bot challenges can still prevent access. TLS, account isolation, Stop and resource bounds remain enforced; no host browser cookies or challenge bypass are added.

The reader now honors HTML section IDs and legacy named anchors, percent-encoded fragments, redirects, duplicate/hidden anchors and explicit offsets. It keeps the entire cached text for paging/find and reports original-text positions for case-insensitive Unicode matches. This production repair was authored independently by Codex and passed all 12 benchmark checks; it is not a Qwen self-improvement success. Structured web evidence projection retains contiguous preview records, source links and honest continuation offsets instead of silently skipping omitted records.

Coding support includes an administrator-only source map with filenames, Python symbols and exact read offsets. Optional support for the actual running 1.7B or 4B model adds general task, source-navigation, assumptions, evidence and test guidance. Enable it in Chat Preferences > Tools & limits. It is off by default and does not activate for 27B/unknown models, grant permissions, run actions or enlarge budgets. Observed 4B errors informed the guidance: treating a returned root field as a literal path, using semantic prose in literal source searches, guessing symbols after empty results, and treating plans/edit receipts as verification. These are observed behaviors, not access to a model's private assumptions or a demonstrated universal improvement.

Checkpoint handling now retains recent complete tool exchanges when they fit, rejects tool markup as a summary, and keeps exact history after a failed periodic summary while it still fits. Shared prompt/discovery text was shortened to preserve usable 8K context with Academic policy and small-model support. Academic instructions now also survive the focused maintenance menu. Account policy, minimum reply allowance, context/continuation reserves and effect-replay protections were retained.

Controls > Utilities, OS-matched independent Projection and Full-only Abliterator access, installer locators, optional suite component/installer downloads, and Login recovery/CONFIRM-protected account wiping remain included from r47. Each live SSD and its installer copies remain independent. The published Abliterator installer remains Windows-only; no new Linux/macOS Abliterator package is included.

Broader self-improvement evaluation
No completed broader coding trial passed the complete independent acceptance rule. This does not establish a general model intelligence limit.

The task describes website-reader behavior and acceptance criteria without naming its implementation file or method. Trials use real NativeChat.agent_worker, authenticated synthetic administrators, local inference, actual tools, frozen disposable public source, a separate pinned checker, saved outgoing requests and tool receipts. A pass requires changed source, all acceptance checks, the model running a passing checker against the same source hash, normal profile sealing and no timeout. Official-document fetches are listed separately: snippets/search results are not documentation reads. Success retrospectives are concise self-reports about methods/assumptions; independent receipts remain the evidence.

The initial native trials used 16K. Retained trials use 32K, keep 12 recent tool exchanges and use a 24-exchange periodic checkpoint interval; 4B support off/on shares the same source, task, tools, budgets and checker. If listed, broad27-no-thinking is a separate control with the same 4096-token reply cap and template reasoning disabled, not the shorter Fast-profile allowance. The intermediate scaffold diagnostic was deliberately interrupted after premature checkpoint loss was found, then restarted after repair; it is not a completed model failure. Frozen evaluation snapshots deliberately retain the defect and are not replacements for the repaired installed application.

The evaluation shell is limited to declared search/check helpers; file writes stay within the disposable public source. This is a harness restriction, not the ordinary administrator coding interface, and must be considered when interpreting failures. The helper/checker hashes are pinned so only those known read-only checks can repeat; arbitrary shell writes retain replay protection. Tests run in bounded subprocesses, not an OS security sandbox. Windows CUDA evaluation loads used the existing 27B Full abliterated Q4, standard 4B Q4 and 1.7B Q8 models, with a 3 GiB reserve and no installed hardware-policy change. Different generations/quantizations and single-task samples do not isolate parameter count. The Academic 27B variant was not evaluated here.

Sampling control: earlier trials used temperature zero, which is a limitation of those comparisons. The separately labeled sampled control uses temperature 1.0, top_p 0.95, top_k 20, min_p 0, presence_penalty 0 and repeat_penalty 1, with medium reasoning and up to 8192 reply tokens. Those sampling values follow the Qwen3.8-27B thinking-mode guidance at https://huggingface.co/Qwen/Qwen3.8-27B/blob/main/README.md (consulted 2026-10-27). The same frozen retained source, task, tools, checker and 30-minute limit remain. Changing both sampling and reasoning allowance makes this a practical diagnostic, not a one-variable experiment. First-request generation settings are saved in model-trial-results.json. If 27B succeeds, additional smaller-model trials use the same task and sampled control settings; they are listed separately, with no inference that these are vendor-optimal settings for every model family.
