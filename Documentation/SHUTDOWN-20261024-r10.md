# Shutdown and Projection repair — October 24, 2026 r10

Exit could stop accepting file-restoration requests and then ask that disabled
service to list mission histories. Shutdown failed before sealing while the
elapsed timer continued to run. The reviewed fix writes Stop controls from
available mission metadata, invalidates schedule epochs, and preserves uncertain
actions for explicit review. It never needs to restore dormant mission bodies to
stop them. Failed shutdowns retain their phase and error class and stop the timer;
Retry starts a new attempt. The app closes only after verified sealing.

Windows minimize now posts its native command through Tk's message loop.
Projection can delete a selected saved connection through an internal themed
confirmation requiring `CONFIRM`. This deletes only the selected local encrypted
connection and its public pairing export; approval in Home Assistant is separate.

The cumulative Aoostar handoff also contained its temporary mission-import
workflow. That menu, importer and startup flags remain excluded from every public
application and installer. Existing private connections, legacy receipts, missions
and schedules remain compatible. No user records are removed or run by this update.
Donation and executable-recovery controls, native Mac support, Academic model
restrictions and current download/storage/integrity checks are preserved.

Use the current Full or Academic installers for a fresh installation. Existing
installs need a source-aware update; normal restart loads updated source. Older
setup launchers remain pinned to their original release. Keep older downloads
until an interrupted installation is safely resolved.

[Receiving validation](SHUTDOWN-VALIDATION-20261024-r10.json) records disposable
account tests, actual Stop-child/sealing checks and owned-process tests. Native
Linux/macOS, Aoostar/HA deployment and a complete fresh optional-dependency
installation were not performed on this Windows host.
