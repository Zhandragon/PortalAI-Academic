Nice web search and saved evidence repair - October 24, 2026

Reported failure
The pasted web return was the help action's successful response: an actions
dictionary and rules, without any search results. Nice nevertheless described
a successful product search and offered to retrieve missing details later.
That return does not establish whether a separate earlier search ran.

Confirmed causes
1. Native web exposed page/browser/API operations but no search action. Search
   existed only as the separate registered Agent/web_tools.py command.
2. chat_working_memory.evidence_lines preferred generic reported fields. For
   the help envelope it reduced the evidence to ok: True. For native search
   envelopes it also discarded titles, URLs and snippets. Large CLI results
   could similarly lose useful middle content during projection.
3. Guidance did not clearly distinguish help discovery from search findings;
   the generic instruction to answer on success could encourage early closure.

Installed changes
- web(action=search, arguments={query: ...}) calls the existing bounded search
  provider/cache implementation. limit is 1..12; fresh is a boolean. No browser
  is started for this action. Existing TLS, provider cooldown, captured-profile,
  Stop, and worker ownership behavior is retained.
- Help is explicitly tool_help and says no search was performed. Search results
  carry search_results and identify their content as snippets, not fetched pages.
- Native tool schema and compact/full guidance describe search, page reads,
  answering with source links, and retrieving specific omitted evidence.
- Bounded evidence projections preserve paired titles, exact URLs and snippet
  prefixes for native and CLI searches. Too-long URLs/results are omitted whole
  with counts and a source message_id for exact chat_history retrieval. Original
  transcripts and execution receipts remain unchanged. Legacy help is labeled
  as discovery in rolling evidence; failed results retain their failure status.
- Only native help/search are added to the read-only format-recovery classifier.
  Browser actions and HTTP requests remain conservatively effectful. No automatic
  tool invocation or replay was added.
