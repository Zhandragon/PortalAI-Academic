PortalAI account setup startup correction - 2026-10-24

The normal control_center_bootstrap.py now accepts --account-setup and optional
--account-setup-receipt. It forwards these literal data paths into the GUI after
the same dependency preflight, module-path preparation, instance registration
and diagnostics used by normal PortalAI.exe startup. Normal sign-in and the
authenticated administrator import remain required. No credential is passed
in arguments, environment or a setup request.

The one-time prepared launcher had called PortableAI_GUI.py with isolated Python
directly, which exited before sign-in because ControlCenter imports were absent.
Use Runtime/BootstrapPython/pythonw.exe -B -I ControlCenter/control_center_bootstrap.py
with the setup arguments instead. PortalAI.exe remains the normal day-to-day entry.
The bootstrap computes its own root; an alternate --root argument is refused.

Four regression tests check default startup, literal path forwarding, invalid
arguments and the normal preflight/instance/diagnostics/cleanup sequence. Existing
r35 connection and profile tests remain applicable. This correction changes no
credential formats, authorization, mission data or schedule activation behavior.
