PortalAI r49: practical code navigation

Chat Preferences > Tools & limits > Focus tools on coding and maintenance exposes the compact coding workflow. The underlying tools are available to all model sizes with the existing administrator permissions. Optional low-power support remains available for actual running 1.7B and 4B models.

Start with inspect_environment. It reports this installation, the account workspace and the bundled Python; these are distinct locations. source_map(query="short feature words", limit=6) ranks public files using observed filenames, Python symbols and docstrings. Ranking is lexical, not a guarantee that a file is responsible. Read the observed code before deciding.

source_map(path=an observed Python file) returns qualified symbols, character ranges, imports and ready-to-use read_file arguments. These suggestions never execute automatically. Both source tools accept their returned absolute paths or paths relative to this installation. Paths in another installation, private folders, parent traversal and linked files remain rejected. Administrator access and Stop are rechecked.

source_search defaults to the public source roots recursively (Agent, ControlCenter, Tools, Documentation, Maintenance/Tests). Only the Tests subtree of Maintenance is exposed; validation records, backups and account data are excluded. It matches literal text or qualified Python symbols, not regular expressions or natural-language prose. Directory searches return one excerpt per matched file to avoid spending all results on the first module. Use a specific file and its character offsets for additional matches. An empty literal lookup also returns up to three ranked candidate files across the public roots, clearly labeled as suggestions rather than matches. This read-only fallback avoids requiring another guessed function name. All scans are bounded and report incomplete scans/pagination. Python source is parsed without importing it.

Maintenance guidance encourages a short reproduce/read/edit/test loop. After repeated discovery calls without an edit attempt, a brief cue suggests following observed symbols/imports and running the supplied checker. After a write attempt it reminds the model to inspect the receipt and verify current bytes. Cues use tool-call names, not instructions extracted from web pages or source content. They neither authorize an operation nor prove it succeeded. No automatic writes, retries, extra permissions or model-resource changes are introduced.

Live self-improvement must still use the guarded staged updater and normal Exit/sealing. No model is allowed to treat a write receipt as passing tests. Trial outcomes, context differences and hardware admission are reported separately in Validation-r49.txt; these navigation features are not a guarantee of autonomous coding success.

When context is compacted, source results retain candidate rank, reason, exact symbol ranges and read offsets in a bounded structured view. A compacted match keeps a contiguous source excerpt with an honest continuation offset. Omitted details remain in exact chat history. Descriptive source text stays untrusted evidence, never authorization.

Source-map views also retain total_items and next_offset. Use the latter as source_map's offset with the same path/query to retrieve the next symbol/file page. These listing indexes are distinct from read_file character offsets. Exact chat history contains only the page originally returned, so it cannot recover unrequested later symbols. omitted_items counts entries omitted from the current returned page during compaction.

Inventory visits the public roots before deeper bundled dependency trees, so a large installed tool cannot consume the scan limit before top-level documentation is considered. Python outlines retain UTF-8 BOM character positions to match read_file text. The frozen navigation4 experiment predates these two edge-case corrections and does not test large dependency trees or BOM source.

The newest tool result in the current user turn receives up to 4,000 characters when older results need smaller views. Its actual projected size is charged to the existing context budget; it shrinks too if needed to retain minimum reply space. This lets source/history reads show useful code without raising model context, resource budgets or user limits. Saved receipts remain unchanged. The preferred reply allowance can decrease to make room for evidence; it remains a ceiling, not a reserved entitlement. The navigation5 experiment includes this change.

source_map(tool="registered_tool_name") inspects the public dispatcher already loaded by this installation and returns observed imported symbols or methods with exact source positions. This avoids guessing an implementation filename from a tool's display name. Python outlines also show existing local script references and imports, including worker hops. These are bounded static observations; dynamic dispatch may not resolve, ambiguous imports are labeled, and none of the inspected code is imported or invoked. Private/other-install paths, links, Stop and administrator guards still apply. No task-specific implementation path is embedded in this feature.

Compact environment evidence prioritizes the actual OS, shell, account permissions, application root and bundled Python before redundant paths. Optional 1.7B/4B support explains tool routing and public test discovery. Source scans validate authorization before each file read and before returning results. In-memory AST traversal checks cancellation without repeatedly rereading account storage for each syntax node; filesystem access still uses authenticated path checks. No authorization result is cached across calls.

Checkpoint guidance lists up to twelve recent valid saved-result IDs with tool names, even when a short result did not need context compaction. It explicitly permits omitting optional evidence_ids. The list contains host message indexes and tool names only, never source/web prose, and its size is charged to the existing context budget. Invented IDs, user/assistant messages and history/checkpoint results remain invalid citations; budget, Stop, login and no-replay rules are unchanged.

If a history summary is rejected, empty or larger than its input, the panel remembers only a digest of that failed request. New tool results in the current turn do not trigger repeated inference over identical older history. Changed older evidence, prior memory or budget allows a fresh attempt; explicit forced compaction can also retry. Raw messages and saved summaries remain intact, and normal context admission, Stop and login checks still apply.

Navigation10 also retains up to 3,000 characters from the preceding tool result alongside up to 4,000 from the newest result in the current user turn. This allows two related source views to remain useful together. Both actual sizes count against the same context budget and shrink when necessary; a new user turn clears both promotions. This changes evidence allocation, not model capacity or minimum reply/safety reserves.
