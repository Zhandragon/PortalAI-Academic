1. **Prepare the drive:** NTFS for Windows, APFS for Mac, or executable ext4 for Linux. [Requirements and drive preparation](Documentation/INSTALLATION.md).
2. **Extract the entire bundle** into a new folder. Keep its files together. Open **Start Setup.cmd** on Windows, **Start Setup.command** on Mac, or run **bash prepare-setup.sh** on Linux.
3. **Choose the installation root and components.** Setup suggests the drive root. Applications use **PortalAI Windows**, **PortalAI Mac** or **PortalAI Linux** there, with selected companions in the sibling **Utilities** folder. **All components** selects the complete Windows catalog; **Express** stays lightweight. Models download during setup.

**Already installed?** Exit PortalAI normally, then choose **Update existing** on Windows or use the native **--upgrade** workflow on Mac/Linux. [Setup, optional utilities and upgrades](Documentation/CURRENT-DOWNLOADS.md).

**Platform status:** Windows has received extensive runtime testing. Mac and Linux remain experimental r75, with fewer validated features than Windows r85. Universal includes separate installers; each OS needs its own native installation. Windows installers are unsigned. See [requirements and known limitations](Documentation/INSTALLATION.md).

## What you can do

PortalAI keeps supported chat, tools, science, images, video, speech and music on your own host. Models, saved projects and accounts can travel on a suitable external SSD or USB drive. Installation needs internet; supported local workflows can run offline afterward. Optional web tools and Home Assistant use your chosen network.

- **Hardware-aware models:** load and offload supported models as needed, with manual model and backend controls.
- **Long tasks and saved missions:** compact working context, retain searchable history, and explicitly enable missions or scheduled work.
- **Local accounts:** password-protected user vaults seal on normal Exit; Guest remains shared.
- **A flexible interface:** full or compact chat, hands-free voice, built-in Help and context-aware right-click actions.

## Privacy and local accounts

This repository provides the public Academic installer distribution. Recipients create their own PortalAI accounts and Projection pairings; the download is not a copy of the maintainer's active personal workspace.

Password-protected accounts encrypt stored user vaults. Files are decrypted while that account is in use and sealed on normal **Exit PortalAI**. **Minimize to tray** and **Stop projection** do not sign out or seal the workspace. Guest is shared, and unlocked data remains accessible to software with the same operating-system access. Keep the host and drive available until shutdown completes.

## Antivirus and the llama.cpp server

Antivirus software may flag or quarantine PortalAI's llama.cpp local model server (`llama-server.exe` on Windows), its supporting libraries, bundled runtimes or the unsigned launcher. This can prevent chat models or workflows from starting and cause local server connection errors. A detection is not by itself proof of either malware or a false positive.

Check the blocked file's path and detection name, verify its source and expected SHA-256 checksum, and review the alert before restoring it or approving a specific file exception. Students should ask their instructor or IT administrator to review the alert. Do not disable antivirus globally or exclude the entire PortalAI folder. Include the antivirus product and detection name in a report to the maintainer, without submitting private data.
