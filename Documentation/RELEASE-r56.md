# Windows r56 — context repair and on-demand tool loading

Short typed or hands-free greetings could overflow an 8K context because every request carried all tool definitions and unrelated workflows. Nice now starts with a small capability index, then loads up to four exact schemas and their relevant workflows using `tool_help`. New selections replace old ones. The tested greeting input dropped from about 6,300 estimated tokens to about 2,000.

Fast, Balanced and Deep share the repair. Each request refreshes actual server capacity after effort switches or voice handoff. Manual caps cannot invent unknown capacity, and training limits are not treated as allocated context. Reply ceilings adapt within the original safety/continuation reserves. Saved messages and account/Stop/Academic policy remain intact. Documentation loading grants no permission and executes no actions; unloaded or mixed discovery/action calls cannot bypass dispatch guards.

Validation: 508 regression checks per D/E installation and exact extracted Windows edition (507 passed, one existing skip); 45 installer checks per edition (44 passed, one existing skip); seven embedded resources and compiled Academic launcher preparation. Real Fast 1.7B/Piper, Balanced 4B/Qwen TTS and Deep 27B/Qwen TTS voice loops used real prompts/admission, synthetic WAV input, Whisper, audio-device playback, visible replies and resumed listening. The 1.7B model also selected documentation, read a file and switched tools to write a verified new file. No physical microphone or complete fresh recipient installation is claimed.

No new dependency, model weights or background service. D: and E: remain independent. Windows installers are r56; Linux/Mac remain r51. Exit and reopen PortalAI normally to activate the update.
