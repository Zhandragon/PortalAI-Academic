PortalAI release validation - 2026.10.27-Desktop-r49

r49 improves how coding models discover and follow PortalAI's own public source. source_map ranks observed filenames, Python symbols and descriptions; a file outline supplies qualified symbols, imports and exact character ranges. source_search defaults to recursive public roots, accepts returned own-install absolute paths, avoids spending a directory result on repeated matches in one file, and offers clearly labeled observed candidates after empty literal searches. Scans are bounded and report truncation. Inspected Python is parsed, never imported.

A confirmed context defect previously reduced rich source discovery results to bare filenames at the 750-character tool-view limit. The new structured projection preserves candidate rank, score, description and exact locations within that same limit, marks omissions and points to exact saved history. Literal snippets stay contiguous and report honest continuation offsets. Paths and symbols are never clipped into different identifiers. Environment views preserve this installation's root and actual permissions. Untrusted source descriptions remain tool evidence, not system instructions. Final production validation also found and corrected deep bundled dependency trees starving later public roots, and UTF-8 BOMs shifting character offsets. Inventory now visits the public roots before deeper trees, and outlines retain BOM positions. Frozen navigation4 trials predate these two edge-case corrections; their public snapshots have no BOM Python files or large installed dependency trees, so these cases were validated separately and are not claimed as tested model-trial improvements.

Brief maintenance cues now use observed tool-call names to discourage repeated discovery without testing or editing and to require verification after a write attempt. The optional low-power module remains available to the actual running 1.7B and 4B models in Chat Preferences > Tools & limits; it remains off by default. General navigation improvements are available to all model sizes. Neither guidance nor the optional module grants permissions, takes automatic actions, enlarges resource budgets or proves success. Administrator checks, Stop, account isolation, private/other-install path rejection and the guarded live-update process remain active.

source_map(tool=...) now locates the public dispatcher already loaded by the current runtime, shows observed imported handlers or method locations, and supplies exact read positions. Python outlines also expose existing local worker-script references and imports. Unknown names return observed dispatch names, explicitly not a permissions list. This follows real source structure rather than a task-specific hardcoded filename. It never imports or invokes inspected code. Dynamic routing may not resolve, ambiguous imports are labeled, and private/other-install paths remain rejected. The generic route feature was frozen in navigation6 and passed 407 unit checks plus all six installer validations. Its unstarted model comparison was superseded by the combined navigation9 experiment after later concrete defects were found; navigation6 itself has no model outcome.

Navigation7 preserves OS and shell in compact environment evidence and makes the public Maintenance/Tests subtree searchable without exposing other maintenance records. Optional small-model guidance explicitly includes tool-route and test discovery. Source scans no longer repeat complete account validation multiple times around the same read or for every in-memory syntax node. They retain authorization before each read and before returning results, cancellation during traversal, and all path/link checks; there is no permission cache across calls. A same-host A/B/A diagnostic measured ranked discovery at 15.1/7.8/17.8 seconds and an outline at 12.4/1.3/14.0 seconds. This includes profiler overhead and is not a general speed guarantee.

The navigation7 disposable input also includes a byte-identical readable copy of the acceptance tests. An earlier model tried to inspect the external checker and was correctly denied by the evaluation filesystem limit. The original checker still executes independently and retains the exact same bytes and grade rules. The prompt still does not name the implementation file or provide a repair; inspecting ordinary tests can reveal their imports. This test-access change is recorded explicitly rather than presented as an identical-harness intelligence comparison.

Navigation7 passed 414 unit checks but was superseded before any model launch. Navigation8 combines those changes with a checkpoint ID catalog and passed 418 unit checks; it too was superseded before model testing. Earlier 4B/1.7B responses supplied invalid evidence IDs, while ordinary short tool views did not expose IDs at all. Current cycle guidance lists up to twelve recent valid IDs with tool names and explicitly permits omitting optional citations. It never copies retrieved prose into host instructions, and its full size is charged to context admission. The original validator still rejects invented IDs and non-result/history/checkpoint references; Stop, account and no-replay checks remain unchanged.

Navigation9 passed 420 unit checks and all six installer validations but was superseded before model launch. It preserves total_items and next_offset in compact source-map results. The navigation5 trace exposed a 21-symbol file outline whose first12 symbols were displayed without its next-page cursor; the reader method was on the unseen page. Guidance now distinguishes a source-map listing cursor from read_file character offsets and explains that saved history contains only the returned page. This correction makes later symbols discoverable without adding a task-specific hint.

Navigation10 is the final combined comparison. The navigation5 trace also showed repeated identical rejected older-history summary requests and rapid loss of the preceding source view. The panel now keeps a digest of a failed summary request and retries when its older input, prior summary or budget changes, or when compaction is explicitly forced. It never commits a rejected summary. The two newest tool results in the current user turn can retain up to 4,000 and 3,000 characters, both fully counted against the existing context budget and shrunk when minimum reply room requires it. These changes do not expand the model context or resource limits.

The r48 website reader and expanded search, direct-site, public catalog, structured-data and resource-discovery capabilities are retained. The production fragment-reader repair was authored by Codex, not Qwen. Controls > Utilities, independent OS-matched Projection and Full-only Abliterator, installer locators, optional suite downloads, Login recovery and CONFIRM-protected account wiping remain included. The published Abliterator installer remains Windows-only. Each live SSD and its installer copies are independent.
