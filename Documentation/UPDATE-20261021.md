# PortalAI Academic: web tools, collaborating agents and Mac projection

Release [v2026.10.21-r2](https://github.com/Zhandragon/PortalAI-Academic/releases/tag/v2026.10.21-r2).

The Windows, Linux and Mac installers include the web reader (HTML/text and PDF pages), Playwright/Chromium page interaction, HTTP API requests, harness schemas, master instructions, configurable service ports and local agent communication. A fresh-extraction check caught a missing portable certificate asset; all six current packages now include the exact public CA bundle pinned by the web client and its license. The shared installer asset helper verifies and includes it in future builds.

Named agents in one installation share its model/runtime and serialize mission steps. Separate sibling installations, on one SSD or on multiple drives, can pair on the same computer and exchange messages or explicitly enabled delegated tasks. Pair in both directions for bidirectional initiation. There is one controller per root and cooperative GPU admission; available RAM/VRAM still limits concurrency. Configure automatic or manual ports under **Settings > Web and agents**, then exit normally and restart. Conflicts fail without terminating another listener. Pairing is session-scoped and loopback-only; LAN/internet swarming is not implemented. Stopping a sender does not cancel work already delegated to another installation.

The [Mac projector and HA setup bundle](https://github.com/Zhandragon/PortalAI-Academic/releases/download/v2026.10.21-r2/PortalAI-Mac-Projection-HA-20261021-r1.tar.gz) supports Intel and Apple silicon Macs, requires macOS 14+, and includes its own Python/Tk/TLS runtime. Both Mac installers include this utility beside the installer. Keep Utilities outside the installed PortalAI account root. ScreenCaptureKit projects verified PortalAI windows; desktop projection requires Screen Recording permission. HA Native controls are available separately. The HA receiver remains **0.5.11 + Recovery 0.1.0**; no new incompatible server protocol is introduced. Recovery requires separate pairing and local arming. Read [Mac setup](MacProjection/SETUP.txt) and [the Projection guide](PROJECTION.md).

These are clean installers. Existing account roots are refused; they are not automatic in-place updaters. No personal accounts, connection keys, browser profiles or model output history are included.

## Validation and limits

The prior WebAgents checks include 293 Full Windows extracted-source tests (one expected skip), 23 Academic policy tests per platform, 20 Academic web/agent checks, Windows browser interaction and sandboxed Linux Chromium execution. Mac packaging checks include 19 Mac contract tests, native-extension architecture checks, 125 host tests (one skip) and 17 HA installer tests. Three companion TLS fixture errors reproduced with the original transport; they remain documented. Live model restoration timed out in a disposable fixture and is not counted as passing.

Physical Mac installation, Screen Recording/Retina behavior and live HA deployment remain untested. Native Linux desktop and complete recipient installs also need acceptance. Windows-side source/archive checks do not establish native Mac compatibility. See [publication verification](PUBLISH-VALIDATION.json), [WebAgents results](WebAgents/validation-final.json) and [Mac results](MacProjection/validation.json).

[Web, agent and port instructions](WebAgents/USAGE.txt) describe tool limits, pairing and safe shutdown. Web tools do not bypass website authentication, CAPTCHA or TLS, and reject private/loopback HTTP targets; peer communication uses its own channel.
